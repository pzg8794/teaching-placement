## ♿ UDL and Inclusion Supports

### 👀 Multiple Representation
- 👀 Show condition language with if/when visuals and concrete trigger examples.
- 👀 Use a two-column chart: if this happens / then robot does this.
- 👀 Demonstrate one true-case and one false-case outcome.

### ✍️ Multiple Action / Expression
- ✍️ Allow students to predict with cards before coding.
- ✍️ Provide prewritten conditional sentence frames.
- ✍️ Use paired testing roles so one student watches the condition while the other launches code.

### ❤️ Multiple Engagement
- ❤️ Use visible cause-and-effect robot behavior to make logic concrete.
- ❤️ Keep tasks framed as puzzles with more than one test round.
- ❤️ Invite students to guess what the robot will do before it runs.

## 🗣️ Teacher Moves / Script / Routines

- 🗣️ Model a non-conditional program first, then show what changes with a condition.
- 🗣️ Ask students to test both outcomes instead of only the successful one.
- 🗣️ Use debug talk that distinguishes wrong code from wrong trigger conditions.
- 🗣️ Close with a comparison between sequence-only and condition-based solutions.

## 🐞 Common Errors and Debugging

- 🐞 Students may think a condition is just another step, not a decision point.
- 🐞 Sensors can create inconsistent results if the environment is uncontrolled.
- 🐞 Students may test only one branch and assume the program works.

## ↔️ Extensions and Simplifications

- ↔️ Extension: chain more than one condition or compare two conditional solutions.
- ↔️ Simplification: use one obvious trigger and one obvious response.
- ↔️ Extension: ask students to explain the logic in plain language before showing the blocks.
