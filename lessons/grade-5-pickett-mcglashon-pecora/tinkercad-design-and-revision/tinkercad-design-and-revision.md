## ♿ UDL and Inclusion Supports

### 👀 Multiple Representation
- 👀 Project the workspace and name only the tools needed for the current task.
- 👀 Use side-by-side before/after screenshots to show revision value.
- 👀 Keep navigation vocabulary tied to visible actions.

### ✍️ Multiple Action / Expression
- ✍️ Allow students to sketch first, then build.
- ✍️ Provide a starter file or partially built model for students who need lower entry load.
- ✍️ Accept oral explanation of design choices in addition to written reflection.

### ❤️ Multiple Engagement
- ❤️ Use real object examples so the design has a concrete target.
- ❤️ Frame revision as improvement, not mistake-fixing.
- ❤️ Let students compare two design choices and defend one.

## 🗣️ Teacher Moves / Script / Routines

- 🗣️ Model one object by decomposing it into shapes before touching the software tools.
- 🗣️ Pause after the first shape placement to make sure all students are in the same view.
- 🗣️ Show grouping and hole tools as solutions to a design problem, not as disconnected features.
- 🗣️ Close with a revision share-out.

## 🐞 Common Errors and Debugging

- 🐞 Students may get lost in navigation and view control before understanding design concepts.
- 🐞 Grouping too early can make editing harder.
- 🐞 Students may overbuild without checking whether the design still matches the goal.

## ↔️ Extensions and Simplifications

- ↔️ Extension: redesign the object for a different user need or constraint.
- ↔️ Simplification: provide a three-shape target with fixed measurements.
- ↔️ Extension: compare two design plans and choose the more efficient build process.
