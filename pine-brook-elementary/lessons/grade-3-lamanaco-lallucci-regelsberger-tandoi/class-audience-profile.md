## ⚡ Quick Scan

- **Class block folder:** `grade-3-lamanaco-lallucci-regelsberger-tandoi`
- **Audience type:** Upper-primary learners who can sustain design and robotics challenges when the structure supports collaboration and debugging.
- **Design lens:** Use challenge-style slides with strong checkpoints, partner-role prompts, and visible debugging language.
- **Use this for:** pacing, partnering, slide design, tool setup, and support planning

## 👥 Recurring Support Needs

- Partner norms that keep one student from dominating the device or the robot.
- Scaffolds for translating ideas into code, then code into revision steps.
- Frequent reminders to slow down, test one change at a time, and notice patterns.
- Help with organizing materials and keeping track of progress in multi-step build lessons.

## ✅ What Helps This Class

- Use challenge slides that make the success target visible without overloading the screen.
- Build in peer-check moments where students explain what changed and why.
- Name debugging as normal and expected so mistakes feel like part of the lesson, not failure.

## ⚠️ What To Adjust Next

- Use stronger stop points between test rounds so revision stays purposeful.
- Show more side-by-side examples of not-yet and ready work.

## 🎨 Presentation Rules For This Class

- Keep slides low-density and action-forward.
- Use repeated icons and colors so students can re-find the same kinds of information quickly.
- Make the help routine visible before students need it.
- Show what success looks like, not only what to do first.
