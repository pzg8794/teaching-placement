\section*{UDL and Inclusion Supports}
\subsection*{Multiple Representation}
\begin{itemize}[leftmargin=*]
\item Project the exact menu path and keep it visible during startup.
\item Use one shared visual for command vocabulary such as move, turn, loop, and agent.
\item Show the objective and the success condition before students start coding.
\end{itemize}

\subsection*{Multiple Action / Expression}
\begin{itemize}[leftmargin=*]
\item Allow students to plan with arrows or pseudocode before placing blocks.
\item Use partners strategically so one student navigates while the other checks directions.
\item Provide a “help checkpoint” routine: read objective, test one block, ask after trying one fix.
\end{itemize}

\subsection*{Multiple Engagement}
\begin{itemize}[leftmargin=*]
\item Use challenge progression and visible level goals to sustain attention.
\item Normalize being stuck as part of coding, especially in the boss-level and timed tasks.
\item Keep free-build desires acknowledged but separated from the current lesson purpose.
\end{itemize}

\section*{Teacher Moves / Script / Routines}
\begin{itemize}[leftmargin=*]
\item Start by naming the lesson purpose and separating it from free build mode.
\item Model the exact clicks to reach the lesson world, then pause for students to mirror.
\item Require students to read the challenge objective before placing blocks.
\item Stop mid-lesson to share one debugging pattern that is working.
\item Close with a brief reflection on the challenge, bug, and fix.
\end{itemize}

\section*{Common Errors and Debugging}
\begin{itemize}[leftmargin=*]
\item Students may get lost in sign-in or library navigation before reaching the lesson.
\item Students may ignore written directions and brute-force the level.
\item Timed or dual-goal levels can overload students if they do not break the task into parts.
\item Some students may confuse avatar movement and agent movement.
\end{itemize}

\section*{Extensions and Simplifications}
\begin{itemize}[leftmargin=*]
\item Extension: ask students to optimize a working solution with fewer blocks or more elegant loop use.
\item Simplification: provide a partially completed block stack or a paper path plan first.
\item Extension: add a reflection comparing two different solutions to the same level.
\item Simplification: assign a fixed partner role split for navigation, coding, and checking.
\end{itemize}
