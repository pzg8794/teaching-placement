# Teaching Placement Presentation & Visual Material Standard

**Status:** Canonical cross-placement design/process standard for student-facing and presentation-facing visual materials.

**Applies to:** PowerPoint decks, PDFs, posters, flyers, handouts, visual review activities, teacher presentation aids, and any teaching-placement artifact in which visuals materially affect instruction.

**Primary rule:** **Visuals teach; they do not merely decorate.**

This standard captures the workflow refined through the September 2026 Marketing materials and should be used across K–5 and 6–12 placement work unless a newer, explicitly approved standard replaces it.

---

## 1. Start from evidence, not from a blank design

Before designing slides or visual materials:

1. Read the **newest relevant placement evidence**:
   - current SBTE/mentor feedback,
   - newest de-identified transcript summary or private transcript when authorized,
   - current textbook/source pages,
   - current lesson/deck,
   - current stopping point,
   - latest student-facing examples already used in class.
2. Separate:
   - **verified current state**,
   - **SBTE/mentor request or feedback**,
   - **student examples/words**,
   - **teacher proposal**.
3. Do not invent completion, student responses, class progress, or approved activities.
4. If students already completed an activity, design the next visual as **review/retrieval/application**, not as if they are building the same concept for the first time.

### Evidence hierarchy for classroom visuals

Prefer, in order:

1. newest direct SBTE/mentor direction;
2. newest classroom transcript/current stopping point;
3. authoritative course/textbook material;
4. previously approved teaching artifact;
5. de-identified student examples and language;
6. teacher-generated examples only when needed.

---

## 2. Student language first, academic language second

When students have already generated examples, words, scenarios, or classifications, reuse them.

The default teaching move is:

> **STUDENT EXAMPLE → VISUAL EVIDENCE → ACADEMIC TERM → EXPLANATION**

Examples:

- delivery / timing / pickup → **Place** or **Channel Management**
- survey / rating / feedback → **Marketing-Information Management**
- style / quality / features → **Product**
- attention / message / popularity → **Promotion**

Do not replace student-generated examples with generic AI examples merely because generic examples are easier to design.

Do not attribute an exact phrase or choice to an individual student unless the source supports it and the artifact is allowed to contain that information. Public-safe materials should use **aggregate, de-identified examples**.

---

## 3. Every visual element must have an instructional job

For each photo, illustration, icon, crop, figure, annotation, or visual object, ask:

> **What can a student learn, infer, identify, compare, or explain because this element is here?**

If the answer is only “it looks nice,” remove or replace it.

### Strong instructional visuals

A strong image can help students:

- identify a product or service;
- distinguish one concept from another;
- notice price/value evidence;
- infer access, place, delivery, timing, or channel;
- identify promotion/attention/message;
- see feedback/research evidence;
- identify selling/checkout/purchase;
- identify financing/payment/funding;
- identify a target customer from meaningful contextual cues;
- connect a familiar example to exact course vocabulary.

### Avoid

- decorative stock photos that teach nothing;
- repeated use of the **same image for different concepts** when the visual should distinguish them;
- cute/childish visuals for older students unless deliberately appropriate;
- generic icons when a concrete scenario image would teach more;
- unnecessary visual noise;
- text embedded inside AI-generated images when editable slide text can carry the label more reliably.

---

## 4. Distinct concepts require distinct visual evidence

A key lesson from the September 24 Marketing review revision:

> Reusing the same image across multiple answer categories can preserve visual continuity but can also destroy conceptual discrimination.

If students are being asked “Which concept does this evidence show?”, the images must differ in ways that make the concepts visibly distinguishable.

### Example: Four Ps

Use different evidence for each P:

- **Product:** distinct offerings/features/benefits;
- **Price:** price/value/payment decision cues;
- **Place:** store, pickup, delivery, online access, venue, streaming, timing;
- **Promotion:** ad/message/display/video/awareness/attention.

### Example: marketing functions

Use distinct actions:

- **Marketing-information management:** survey, ratings, feedback;
- **Product/service management:** update, redesign, features, quality improvement;
- **Pricing:** choosing what customers pay;
- **Channel management:** pickup, delivery, retail, streaming, distribution;
- **Promotion:** message, ad, video, poster;
- **Selling:** checkout, ticket, purchase interaction;
- **Financing:** funding or payment option.

Repeated images are acceptable only when the repetition itself is instructionally useful.

---

## 5. Use progressive reveal so students think before the slide answers

For review, retrieval, questioning, and discussion decks, do **not** show the answer immediately.

Default reveal sequence:

1. **Image/scenario first**
2. **Prompt/question**
3. students point, select, write, or answer;
4. **term appears**
5. **reason/explanation appears**
6. optional connection to another term or source page.

### PowerPoint behavior

Use click-controlled reveals wherever possible.

Preferred approaches:

- native object entrance animations when reliable; or
- staged duplicate-slide reveal states with fast, unobtrusive **Fade** transitions when this is more robust.

The classroom experience matters more than whether the reveal is technically implemented as an animation or as sequential slide states.

Do not export only a static deck when the teaching plan depends on withholding answers.

### Reveal-ready layout rule

Answer vocabulary should live in separate text boxes/chips/cards so it can appear after the evidence without rebuilding the slide.

## 6. Design review activities as retrieval, not re-teaching

When students have already built a marketing mix, classification, chart, model, or group example:

Use language such as:

- **Review**
- **Which term does this evidence show?**
- **What do you notice?**
- **Name the term**
- **Explain why**
- **What evidence supports it?**

Avoid framing the activity as “build the concept” again unless actual evidence shows students need to reconstruct it.

A useful routine is:

> **LOOK → SAY THE TERM → EXPLAIN WHY**

or

> **POINT → TERM → WHY**

This supports retrieval while keeping the academic vocabulary explicit.

---

## 7. Keep the visual style mature, coherent, and age-appropriate

For the current 6–12 placement, the successful visual language is:

- warm cream/off-white background;
- deep navy typography;
- teal instructional accents;
- restrained orange emphasis/reveal color;
- realistic or polished editorial/cinematic scenario images;
- rounded cards used for real grouping, not decoration;
- large readable headings;
- generous white space;
- minimal but meaningful text;
- strong hierarchy.

For K–5, adapt the complexity and reading load, but keep the same core principle: **clear, purposeful, instructional visuals**.

Do not default to “cute” because the artifact is educational.

---

## 8. Use multiple creative tools, but the deliverable follows the teaching need

Figma, Adobe, image-generation tools, or other design tools may be used for:

- visual exploration;
- realistic scenario images;
- image crops/variants;
- composition ideas;
- typography or design references.

They are **support tools**, not automatically the final deliverable.

When the user/SBTE needs a classroom presentation, default final outputs are:

1. **editable PowerPoint (.pptx)** with reveals/transitions;
2. **PDF** showing the final-state slides for review/printing;
3. optional **static final-state PowerPoint** as a fallback.

Do not substitute a Figma project for a requested PowerPoint.

---

## 9. Create visuals from the lesson's actual examples

When building a scenario image:

1. identify the exact concept(s) the image should teach;
2. identify the student/class example being represented;
3. include only details that support those concepts;
4. remove unrelated decoration;
5. keep identities fictional/de-identified;
6. avoid visible real school/student identifiers;
7. avoid unnecessary brand/logo dependence;
8. generate or compose distinct variants when different concepts need different evidence.

### Example image brief structure

> Create a mature, realistic classroom-safe scene showing **[scenario]**.  
> Students should be able to notice **[evidence A]**, **[evidence B]**, and **[evidence C]** and connect them to **[terms]**.  
> No readable logos, no student identity, no decorative-only objects.

---

## 10. Build slides around student action

Every student-facing slide should make the expected action obvious.

Good prompts:

- Look first.
- Point to the evidence.
- Choose one.
- Say the term.
- Explain why.
- Write one reason.
- Compare these two.
- What changed?
- Which clue proves your answer?

Avoid slides that depend on a long teacher explanation before students know what to do.

When appropriate, include:

- a visible hard stop/time box;
- a sentence frame;
- a listener job;
- a recorder/participation role;
- an exit check;
- an alternate response mode (pointing, writing, speaking, selection).

---

## 11. Typography and readability

Before release:

- headings must be readable from the back of the room;
- body text should be comfortably readable without zoom;
- enlarge teacher-route/timing slides rather than treating them as dense notes;
- reduce words before reducing font size;
- maintain strong contrast;
- never rely on color alone to convey the answer;
- keep labels close to the visual evidence they describe;
- avoid tiny captions inside large images.

---

## 12. Privacy and provenance

For teaching-placement visuals:

- keep student names, diagnoses, family details, identifying screenshots, and raw transcript details out of public artifacts;
- use de-identified aggregate language;
- record the evidence basis in speaker notes or a companion planning file when useful;
- label teacher-created extensions as proposals, not established school requirements;
- do not claim a student/example/source said something that the record does not support.

Raw transcripts remain private according to repository policy.

---

## 13. Required QA before calling a deck finished

A presentation is **not done** when the PPTX merely exports.

Run all applicable checks:

### Content QA

- current source/stop point verified;
- terminology matches textbook/course language;
- student examples are grounded and de-identified;
- prompts do not reveal answers prematurely;
- review vs. new learning is framed correctly.

### Visual QA

Render every slide to images and inspect:

- clipping;
- overlap;
- tiny text;
- weak contrast;
- inconsistent spacing;
- awkward crops;
- duplicate images that should be conceptually distinct;
- meaningless decorative elements;
- answer labels accidentally visible before reveal.

Create a montage/contact sheet when useful to inspect consistency across the whole deck.

### PowerPoint QA

- validate slide bounds/overflow;
- test slide order;
- test every click/reveal sequence;
- confirm transitions are fast and unobtrusive;
- confirm no reveal state accidentally skips or shows an answer too early.

### PDF QA

- export the final-state deck to PDF;
- render the PDF pages back to images;
- inspect for font substitution, clipping, changed line breaks, missing images, or layout shifts.

### Final deliverables

Release only after both the classroom PowerPoint and final-state PDF are visually inspected.

---

## 14. Versioning and correction discipline

Use clear versions when meaningful changes occur:

- v1 initial;
- v2 pacing/content correction;
- v3 visual redesign;
- later versions for substantive reveal/image/QA corrections.

If a problem is found (for example, the same image being reused where concepts require distinct visual evidence):

1. acknowledge the design problem;
2. fix the source deck, not only the exported PDF;
3. regenerate reveal and static states;
4. rerender slides;
5. re-export/rerender PDF;
6. inspect the affected slides again.

Do not defend a visual choice that weakens instruction merely because it is aesthetically consistent.

---

## 15. Release checklist

Before sharing with the SBTE or teaching from the material:

- [ ] newest transcript/SBTE/source state checked;
- [ ] student examples reused where appropriate;
- [ ] visuals teach rather than decorate;
- [ ] distinct concepts have distinct evidence;
- [ ] student action is visible;
- [ ] answers are withheld until discussion when appropriate;
- [ ] reveal sequence tested;
- [ ] terminology matches the source;
- [ ] layout rendered and visually inspected;
- [ ] PDF checked;
- [ ] privacy/de-identification checked;
- [ ] PowerPoint remains editable;
- [ ] final file naming/version is clear;
- [ ] SBTE-facing message is brief and accurately describes the activity.

---

## 16. Default future instruction

When any AI or collaborator creates a presentation or visual teaching material for this repository, the default instruction is:

> **Follow docs/TEACHING-PRESENTATION-AND-VISUAL-MATERIAL-STANDARD.md. Ground the artifact in the newest evidence, reuse student examples where appropriate, make every visual instructional, use progressive reveal when answers should come from students, keep visuals age-appropriate and mature, and render/inspect the PowerPoint and PDF before release.**

This rule applies across placements unless a placement-specific source requires a different approach.
