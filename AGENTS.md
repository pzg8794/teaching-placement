# AGENTS.md - RESEARCH Repository Operating Instructions

Last updated: 2026-05-31

This repository is the source of truth for Piter Garcia's research, fellowship, and PhD application strategy.

## Critical rule: check the master tracker first

Before giving advice about PhD applications, research opportunities, fellowships, deadlines, country strategy, or application status, every agent must first check:

`APPLICATIONS/PhD/master-application-tracker.md`

Do not rely on memory, chat history, or scattered notes before checking the tracker.

## Required workflow for application work

1. Open `APPLICATIONS/PhD/master-application-tracker.md`.
2. Identify whether the opportunity is already:
   - `submitted / monitor`,
   - `active / build`,
   - `active / verify`,
   - `reviewed / skipped`,
   - `reviewed / no action`,
   - `calendar`, or
   - `monitor`.
3. If the user asks for closest deadlines, answer from the master tracker first.
4. If a new opportunity is discovered, add it to the tracker with:
   - opportunity name,
   - country / route,
   - official source URL,
   - deadline and timezone if known,
   - fit / priority,
   - status,
   - materials needed,
   - next action,
   - date checked.
5. If an application is submitted, update the tracker immediately:
   - set status to `submitted / monitor`,
   - add submission date,
   - add portal/application/confirmation ID if available,
   - add next action: save receipt privately and monitor email/portal.
6. If an opportunity is reviewed and intentionally skipped, update it as `reviewed / skipped` or `reviewed / no action` so it does not keep polluting the active queue.
7. If documents are submitted through external portals, do not store private receipts or sensitive documents in the public repo. Record only safe metadata.

## Repository documentation rule

Every substantive application decision must be documented in the repo.

Use:

- `APPLICATIONS/PhD/master-application-tracker.md` for the live source of truth.
- Per-application notes only when detailed drafting, evidence, or decision history is needed.
- Public-safe metadata only. Keep personal receipts, portal screenshots, transcripts, recommendation letters, and private documents out of public files.

## Response rule for future agents

When answering the user about deadlines or application status:

1. Say what the tracker currently shows.
2. Separate submitted/monitor-only items from active tasks.
3. Identify deadlines due today/tomorrow/this week clearly.
4. Be explicit if the repo is incomplete or if external verification is still needed.
5. Avoid making the user relitigate already-submitted or already-skipped applications.
